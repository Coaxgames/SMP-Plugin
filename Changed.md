- Added a generated Minecraft 26.3 resource pack built from the embedded Blockbench PNGs and models. Crafting previews now explain blocked recipes, including the requirement for Head Drop-marked player heads.
- Added Gradle wrapper files using Gradle 9.6.1 so CI can build without relying on a runner's preinstalled Gradle.
- Added release-version tooling and tests. It compares the Gradle version, `plugin.yml` version, and semantic-version tags; it can honor an already-bumped source version and keeps the Gradle and plugin metadata versions in sync.

- Investigated the actual `Testbuild?` push to `Stable` after the owner reported that no Gradle build/release occurred. That Actions run contained only the `signal` job and did not build Java code. - A change to build all branches and release from the branch pushed was drafted during that investigation, but it is **not present in the current `main` workflow files**. The current checked-in `main-build.yml` only watches `main`, and the release workflow also has a `main`-only gate. Therefore, an owner push to `Stable` is not currently verified to build or publish a release. The release automation still needs a dedicated correction and a real Actions run before it can be considered verified.
- Repository branch protection and Actions permissions were documented but not configured by these code changes. The required settings are described in `.github/RELEASE-AUTOMATION.md`.

## Phase 1 – Core Framework

- Added `LegendaryItem` definitions and a registry that registers per-item listeners and exposes recipe, cooldown, and maximum-craft hooks.
- Added PDC identity using `galaxy:item_id` plus a per-stack `galaxy:uuid`; item creation stamps this identity and identification looks the ID up in the registry.
- Added `LegendaryItemBuilder` support for unbreakable items, hidden item flags, Adventure display names/lore, custom model data, and optional `item_model`.
- Added a config-driven `CooldownManager`. Cooldown expiry times are stored persistently, so active cooldowns survive restarts. Configuration supports `cooldowns.default-seconds` and item-specific overrides.
- Added `LegendaryDataStore` using the plugin data folder's `data.yml`. It persists crafted counts, item ownership, last-known locations, and player/item cooldown expiry. Writes use a temporary file and an atomic move where supported. Invalid persisted numeric values are reported rather than silently treated as valid defaults.
- Added the `/galaxy give`, `/galaxy reset`, `/galaxy list`, and `/galaxy locate` admin command surface, permission metadata, and tab completion. A grant is recorded before the item is delivered and consumes the item's craft quota. Reset clears cooldowns only; it does not reset the permanent crafted-ever record.
- Added JUnit tests for craft-once persistence across reloads, grant ownership/location tracking, cooldown persistence and clearing, item UUID ownership, and malformed craft-count data.
- Added shared `HitCounter` and `DamageCap` helpers after the Sections 2–3.5 audit. `HitCounter` tracks per-player sequences with a configurable timeout, supports deterministic timestamps for tests, and can clear an individual counter or sweep expired counters. `DamageCap` validates inputs and bounds a computed final-damage value; event code still needs to verify the actual Paper final damage after armor/protection modifiers.
- Marked the Phase 1 framework checklist complete after verification. The store/commands are explicitly described as framework primitives: recipe enforcement and live owner/location lifecycle wiring remain in Phase 2, while item definitions and abilities remain in Phases 4–5.

## Phase 2 – Rules Engine

- Added keyed recipe registration to `LegendaryItemRegistry`; prepared crafting results receive the plugin's item ID and unique UUID. The registry enforces craft quotas by item ID, so the Star Mace and Collapsing Star Mace will each have an independent permanent limit when their definitions arrive in Phase 5.
- Verified the Head Drop 3.1.0 jar's Bukkit plugin name (`HeadDrop`) and configuration keys. Added it as a hard `plugin.yml` dependency and a startup check rejecting versions below 3.1.0. Added `HeadDropHead` validation for the `headdrop:dropped` BYTE value `1`; ordinary player heads are rejected in recipes.
- Removed the vanilla mace recipe at startup. Added `PrepareItemCraftEvent`, `CraftItemEvent`, and Paper `CrafterCraftEvent` enforcement with synchronized persistence of the craft count and item UUID/location. Automated crafts can record an unknown owner until a player picks the item up.
- Added protection listeners covering item durability, enchanting-table/anvil/grindstone/Mending routes, container and ender-chest storage, inventory click/drag/shift-click/hotbar swaps, hoppers/droppers, bundles, shulker boxes, item frames, armor stands, and non-player pickups. Player join recovery moves protected legendary items found in ender chests into reclaim storage.
- Added per-item policy hooks for craft-once quota and legendary-only storage/loss protection. Recipe registration rejects shaped recipes that use fixed player-head ItemStacks; dynamic heads are accepted by their Head Drop marker at craft time. Repeated item records do not increment craft-once counts. Ender chests remain forbidden storage for protected legendary items.
- Added a reclaimable barrel at world X/Z `(0,0)` for legendary item hazards/despawn; its marker survives as block-state PDC, the barrel is protected from breaking/explosions, and claiming restores the tracked item UUID. Death drops remain at death location and ownership/location are tracked across craft, pickup, drop, death, quit, recovery, and admin grant.
- Added Phase 2.1 test planning in the roadmap for real Paper/Head Drop integration, crafting modes, protection paths, lifecycle recovery, and restart persistence. At the Phase 2 checkpoint, item recipes were still to be declared in Phases 4–5.
- `gradlew clean test build` passed with 19 tests at the end of Phase 2.1 repository-side validation (including marker value, Head Drop version gating, Paper/plugin metadata, configured gradients, independent mace craft records, repeatable craft-count behavior, and automation record persistence). Live server and future-recipe checks remain pending as recorded in the Phase 2.1 checklist.
- Phase 4 subsequently registered Galaxy String, Kuiper Ball, and Mass Orb as repeatable items without per-stack UUID tracking or legendary-only storage/loss protection. Their carrying-limit behavior is independent from craft-once quotas; Kuiper Ball and Mass Orb are unlimited.
- On 2026-10-25, removed the fixed one-legendary-per-player holding cap at the owner's request, then replaced it with configurable per-item caps after clarification. Each registered item type has an independent limit; the default is one copy per player, an item-specific override is available, and zero means unlimited. Crafting, pickup, inventory movement, join recovery, administrative grants, and reclaiming enforce the configured cap. Server-wide one-ever-per-item craft quotas and protected-container/loss rules remain.
- Added `legendary-items.max-per-player.default` and `legendary-items.max-per-player.items.<item_id>` in `config.yml`. Invalid negative or non-integer configured limits fail plugin startup with an explicit error; older configurations without these keys use the default of one.
- Added configurable per-item display text and two-color hex gradients under `legendary-items.display-names` for all 12 legendary items and three repeatable items listed in Sections 2.1–2.2. The registry applies the configured Adventure name component when creating registered legendary items. `LegendaryItemBuilder` now offers `gradientName(text, startColor, endColor)` and a reusable gradient-component factory for later item definitions and chat messages. Palette values are starter defaults and can be edited in `config.yml`; invalid colors or empty names are reported during startup. Added unit tests for gradient text, endpoint colors, and invalid inputs.
- Recorded the Phase 3 reveal requirements: global announcement, each item's own gradient-colored name, and coordinates formatted as `(X, Y, Z)`. The exact audience and remaining message format stay open. The existing `LegendaryItemBuilder.displayName(Component)` already supports Adventure components, including gradients; the clearest source of truth is a per-item name/gradient entry in config, converted to a reusable display-name component by the builder/item definition. Recipes should remain focused on ingredients and outputs, not presentation. Reuse that same component in death and interaction messages in Phase 6.

## Phase 3 – Ritual System

- Added persisted ritual records with item ID/UUID, crafter UUID/name and coordinates, crafting location, start/completion timestamps, and reveal progress. Craft-once quotas are reserved atomically when the ritual starts and are rolled back if ingredient consumption fails.
- Legendary craft-once results are withheld during the ritual. Player crafting and automated Crafter events consume one ingredient per occupied recipe slot, return material crafting remainders, and restore the original ingredient matrix if startup/consumption fails. Repeatable items keep the immediate-craft path.
- Added the default 900-second ritual and 180-second reveal interval, both configurable and validated at plugin startup. The crafter sees an updating boss bar; portal/end-rod particles animate above the crafting location; the completed registered item drops at that location.
- Added global reveal messages with the item's configured gradient name and crafter coordinates formatted as `(X, Y, Z)`. The audience is global and the remaining message template is configurable; reveal progress is saved before broadcast to avoid repeating a reveal after restart.
- Active rituals resume from saved timestamps. Completion checks for an already-dropped matching UUID before retrying, delays pickup if saving completion fails, and resumes safely on the next scheduler pass. Reclaim barrels persist their world/block coordinates and are rebuilt at startup.
- Added explicit rollback for failed ritual startup and preserved prior reclaim-marker data if a marker write fails. Fixed the join-cap recovery path so it removes only the configured excess instead of dropping every matching item.
- Updated `ROADMAP.md` with the completed implementation and automated-test checkboxes. Live Paper crafting, restart, deadline, animation, and reveal checks remain explicitly unchecked for owner verification; Phase 4 now provides recipes for live item/ritual tests.

## Phase 4 – Simple Items

- Registered Galaxy String, Kuiper Ball, Mass Orb, Astral Sword, Void Sword, Solstice Chestplate, and Lunar Leggings with their shaped recipes and configured display names. Galaxy String and Kuiper Ball are repeatable and omit unique-instance UUIDs so stacks merge; Kuiper Ball crafts 10 and has a max stack size of 64. Kuiper Ball and Mass Orb have no per-player carrying limit, including when an older config specifies the former default cap. Mass Orb is repeatable and has no legendary-only storage/loss rules. Solstice Chestplate and Lunar Leggings now have Protection IV.
- Optimized item pickup handling to immediately accept registered repeatable items that are unprotected and have no carrying limit, skipping unnecessary capacity scans and protection checks for Kuiper Balls, Mass Orbs, and Galaxy String.
- Added Astral Sword's four-hit combo with a configurable 30-second 1.65x attack-speed total multiplier, and Void Sword's four-hit Slowness I/Wither I effect for 10 seconds. The combo window is configurable.
- Added Kuiper Ball projectile freeze and configurable wind-charge-like velocity burst. Added Mass Orb's Slowness IV while held and configurable, explicitly provisional height-damage/cap/Feather Falling reduction parameters.
- Added Solstice Chestplate and Lunar Leggings daily effects at world tick 13,500 with five-minute durations and persisted once-per-world-day triggers. Active effect time pauses on clean shutdown and resumes after startup. Lunar missed-trigger catch-up is configurable and defaults to waiting for the next day's trigger; the owner decision remains open. A process/server crash does not run the clean-shutdown pause, so elapsed wall-clock time can reduce the active duration.
- Added automated coverage for the daily effect persistence lifecycle, Mass Orb formula/cap helper, and Phase 4 config. `.\gradlew.bat test build` passes with 27 tests and no failures. `git diff --check` passes.
- Updated the Phase 2.1 and Phase 3 owner-test checklists because Phase 4 now provides recipes that can be exercised. All live Paper/gameplay checks remain unchecked for owner verification; no texture pack is needed to test mechanics.
- **Bug fix (plugin failed to enable, so no recipes/commands existed):** startup validation of whole-number settings (Phase 3 ritual timings and Phase 4 settings) used `YamlConfiguration#isLong`, which is `false` for ordinary YAML integers such as `900`. The default config therefore threw during `onEnable`, Paper disabled the plugin and unregistered its recipes. Replaced it with `ConfigNumbers.isWholeNumber` and added a test that checks the bundled `config.yml` against these validated paths. Tests: 28 passing. Also added recipe auto-discovery on join/enable and a startup log line with the registered recipe count.
- **Bug fix (v0.1.5 failed with `burst-radius must be a non-negative number`):** decimal settings were read with `getDouble(path, -1.0)` and rejected when that returned the sentinel. The bundled `config.yml` validates fine in tests, so the server read the value differently. Decimal settings are now read directly through `ConfigNumbers.finiteNumber` (accepts numbers and numeric text), at startup validation and at runtime, and the error message now includes the value it found so a bad edited value is identifiable. Note: `saveDefaultConfig()` never overwrites an existing `plugins/GalaxySMP/config.yml`, so a config saved by an older jar keeps its old values.
- **Bug fix (v0.1.5 failed registering the Kuiper Ball recipe):** `Material.POWDER_SNOW` is a block-only material and cannot be used as a crafting ingredient. Changed the recipe to use `Material.POWDER_SNOW_BUCKET`, the craftable powder-snow item. `gradlew test build` passes and `git diff --check` is clean.
- Added a Phase 6 roadmap item requiring every registered item's hover tooltip to clearly present all relevant stats, abilities, triggers, cooldowns, and special rules, kept accurate to configured behavior.
- Clarified that Phase 1's completed item builder is a programmatic API, and added the requested OP/admin-only in-game item/recipe builder/editor to Phase 6. The planned editor covers registered item recipes, display-name gradients, lore, stats, and configurable ability values, with validation and persistent saves.

## Phase 5 – Complex Abilities

- Registered all six remaining Phase 5 item definitions and recipes: Nebula Spear, Wormhole Trident, Celestial Bow, Cosmic Crown, Singularity Boots, and Nova Shield. Recipes preserve custom Head Drop marker checks; Celestial Bow additionally requires Galaxy String in its three string slots.
- Nebula Spear now has Lunge III and uses Paper's native successful `EntityLungeEvent`; every fifth successful lunge launches a forward thrust, deals at most four health points to each target, and starts a configurable 45-second cooldown. Thrust shape/velocity remain config placeholders.
- Wormhole Trident counts successful native Riptides, creates a rift on each fifth activation, launches the creator exactly 20 blocks forward (stopping short of a block obstruction), then keeps the rift active for 50 seconds. Opponents entering it take two hearts and Wither I for 20 seconds. The interaction radius remains a placeholder.
- Celestial Bow now has Power V, Flame, Punch II, and Infinity; fully charged arrows deal configurable splash damage and create a configurable lingering Wither or Poison cloud on impact. Effect choice and balance values remain provisional.
- Cosmic Crown has maximum helmet enchantments and unbreakable protection, provisionally retaliates against the direct living attacker every two damaging hits, and upgrades absorption effects while worn; golden apples grant four hearts of absorption and enchanted golden apples ten. Damage and retaliation target remain open for owner review.
- Singularity Boots now have Protection IV, cancel fall damage, and create a creeper-sized, non-block-damaging explosion after a 50-block fall. Their recipe uses the already-specified center boots, side Breeze Rods, and top/bottom Head Drop heads; the undecided corner positions intentionally remain empty and do not block implementation.
- Nova Shield disables held shields after two axe hits for the configurable timer and automatically restores use when the material cooldown expires. When carrying it, lethal damage is prevented with totem-style effects and a persisted 10-minute cooldown.
- Added validated Phase 5 config defaults for the undecided balances and repository assertions for the new settings. The prior mace tests cover seven-heart input cap, the >five-heart spark threshold, and independent permanent craft records.
- Mace cooldowns now suppress only their abilities, not ordinary melee damage; Collapsing Star Mace sparks do not trigger during the cooldown.
- Applied the test feedback's requested enchantments: Protection IV on Singularity Boots, Solstice Chestplate, and Lunar Leggings; Lunge III on Nebula Spear; and Power V, Flame, Punch II, and Infinity on Celestial Bow. Nebula's Lunge level is fixed at III so an older server config cannot continue generating Lunge I items.
- Improved test visibility for the two reported abilities: successful fifth-Riptide Wormhole triggers now emit a bright portal ring and a creation log; a cancelled custom-trident Riptide logs why no rift was created. Solstice/Lunar effect grants now log success, apply the requested effect unless a stronger one is already active, and warn if Paper rejects an effect.
- `.\gradlew.bat test build` passes with 30 tests and no failures; `git diff --check` passes. The implementation checkboxes are complete. Recipe, effect, cooldown, damage and balance checks in `ROADMAP.md` remain unchecked for owner-local Paper review.
